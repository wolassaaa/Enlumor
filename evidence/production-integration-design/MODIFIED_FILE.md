# Enlumor · 编辑库生产接入设计

日期：2026-10-20。状态：接入方向获用户认可，本文待书面审阅；未修改产品代码、迁移数据库或发布。

## 1. 目标与验收边界

把已完成的编辑库接入实际应用，先让人工编辑可靠地显示、保存、撤销和恢复，再接AI。用户已认可：旧批注完整保留，原文核验成功后转为可编辑，失败继续可见只读，允许手工重新定位。

第一目标闭环：打开真实PDF → 选区或绘制 → 创建/修改/删除标识 → 确认保存 → 撤销/重做 → 正常或异常退出 → 重新打开恢复。新命令不能只在测试宿主成功，实际按钮仍走另一条写入链路。

本轮不重做Cruise、不调用模型，不做前端视觉重写、正文排版、OCR或高级混合高亮。所选快照的真实PDF导出是后续独立门禁；本轮不能破坏现有导出，也不能让旧导出入口声称覆盖新标识。

## 3. 单一存储权威与升级

拟定schema5，在同一个workspace.sqlite中新增edit_marks、edit_versions、edit_anchors、edit_operations、edit_receipts、edit_confirmations、edit_legacy_imports。具体列与索引由后续计划固定，复用既有EditMark/EditOperation/EditReceipt合同，不发明第二套业务模型或sidecar。

- edit_marks保存有效新标识；edit_versions保存对象当前版本及删除墓碑；其余分别保存可信锚点、操作组/定向历史、持久回执、确认凭据及旧行转换状态。
- 原annotations行在兼容期保持原内容、只读，作为历史输入；不是新标识的同步镜像。一个legacy ID只能选择“只读旧对象”或“新标识”作为当前显示权威，不能两份重叠显示。转换映射与新对象同事务提交；旧记录可保留作核对，但不再进入编辑查询。
- documents、reading、preferences、ai_profiles、cruise_sessions等既有数据不重建、不读取密钥。历史人工批注成功转换后origin=user、retained=true、visible=true，保留原ID及源内容；新标识仍默认retained=false，不随切页/关闭面板清除。
- 不在启动时遍历整份论文解析全部旧锚点；结构升级与按文档、按页转换分离。没有源文件时只做可完成的结构升级，保留旧对象，不制造VerifiedAnchor。
- 升级先取得独占升级时段，检查WAL checkpoint忙状态，生成不覆盖既有备份的独立完整备份，并用只读连接核验integrity_check和user_version。备份失败、锁冲突或版本较新均不启动升级。
- DDL、schema版本和必须元数据原子提交。失败回滚并关闭候选连接；恢复只在所有连接关闭后从已验证备份还原，先留存失败库与WAL/SHM，不把旧文件直接覆盖进仍打开的数据库。
- 首轮只使用一次性测试profile和复制的合成v4库；不升级用户个人库或正式0.1.15目录。迁移后旧版拒绝较新schema是预期行为，回退程序须使用迁移前备份，而不是强行降版本。

## 4. 可信原文锚点与旧批注兼容

### 4.1 新文字选区

renderer只提交候选页索引、原生quads和quote；主进程先验证已打开文档身份/源文件指纹，再通过本地PDF组件核验源文字和真实几何，成功才颁发并持久保存VerifiedAnchor。候选坐标不是可信证据，renderer不能提交actor或自造锚点。

新增专用的编辑锚点核验操作；现有Python verify_block只适用于Cruise，采用矩形选字与x排序，限制1200字符/100quads，不能直接当作完整编辑锚点合同。扩展须单独测试字符顺序、双栏、重复句、斜向文字和裁剪页；不可仅比较全页是否包含同一句话。正常匹配使用页与字符/行位置消除歧义，明确固定允许的空白/Unicode规范化规则，不做语义猜测、近似替换或自动搜索到另一处。

输出保持未旋转PDF原生坐标与四个源顶点；pageBounds由源文件解析，正确处理裁剪偏移和负坐标。跨页选区产生逐页锚点，再作为一次批量操作。无文字层时允许画笔、线条、箭头和自由便签，不伪造文字锚点。

源校验和异步解析在事务外执行；缓存以fingerprint及页/解析版本隔离，尺寸/源状态来自宿主。事务内检查缓存所属上下文与锚点版本，不运行Python或等待IPC。暂停、切文档或源变化使在途解析失效，迟到结果不能绑定到新文档。不得为性能跳过既有源文件身份检查；首次锚点准备与普通编辑提交分别测量。

### 4.2 旧对象转换

| 旧对象 | 处理 |
|---|---|
| 高亮/下划线/删除线及带原文便签 | 相同指纹、页、原quote与几何重新核验；成功后赋可信anchorId并原子转换 |
| 自由便签、线条、箭头、画笔 | 在源页界内通过现有新模型几何校验后转换；不凭空增加原文quote |
| 缺源/损坏记录/缺文字层/文字或几何不匹配 | 保留原数据和可用的原显示，标为只读待处理；未知或无效几何不能强行交给新执行器 |
| 同一路径已替换成不同PDF | 按既有SOURCE_CHANGED规则阻止附着旧内容，不在新文件上绘制旧标识 |

转换以documentId/fingerprint/legacyId和输入摘要防重复；同ID已有有效转换或墓碑时不覆盖、不复活。新的文字标识通过真正核验的anchorId进入库，不能把legacy ID改个前缀充当锚点。

“重新定位”是用户明确选择新原文、查看旧/新位置和quote的差异后确认替换；成功才变为新可编辑标识，旧原文留在导入审计记录。失败或取消保持原记录。转换是兼容操作，不伪装成用户刚创建或AI编辑，不加入普通撤销栈；手工重新定位则保留独立、可追踪的用户操作历史。

## 5. 主进程宿主与薄IPC

Workspace复用同一连接实现EditHost/事务端口。BEGIN IMMEDIATE内重读快照、回执、历史与确认，重规划并比较差异，原子写入版本/墓碑、历史、回执和凭据消耗；同步回调成功结束后立即COMMIT；该持久提交点才算已保存。锁忙、磁盘失败、提交结果不明分别处理，不在renderer乐观显示“已保存”。

新增窄桥接能力：取得文档编辑会话/视图快照、准备源锚点、执行人工命令、取消请求、查询持久回执/历史。接口只有固定类型数据，不接收任意IPC名称、SQL、文件路径、JS代码或actor。renderer可使用type-only合同，但不打包node:crypto或主进程执行器。

- 主进程给每个有效文档会话分配context/revision；renderer只能引用已颁发会话，不能自行决定可信revision。来源变化、关闭文档、接管/取消使旧请求失效；新会话重启不改变历史提交事实。
- 人工入口的user actor由宿主给定，ID稳定保存在工作区，不从模型或界面字段取得。本轮不开放AI入口；未来AI actor/session由受控控制器赋予，不能通过人工IPC冒充user。
- requestId在发出操作前固定；重试、确认、未知提交结果恢复均复用原请求。幂等键及请求摘要沿用现有库，不能以“重试”按钮生成新ID掩盖重复提交。
- 对已转换文档的写入口逐个改为编辑命令，迁移结束后旧annotation:change不得继续写新标识。不得同时维护旧UI inverse栈与新历史两个权威。
- 会话、请求、文档/指纹及sender/mainFrame须匹配。保存回执所属文档与当前文档不一致时只记录结果，不改当前画面或跳页。
- 对未知结果只查持久回执；查不到则保留“保存状态待确认”，不自动补发新操作。已提交后取消仍返回已提交事实，需要撤回则新发undo_edit。
- 回执/历史不在首轮自动过期；AI确认凭据不因预览失败消耗。界面关闭不自动删未固定标识或清除已提交历史。

## 6. 阅读器投影、工具与历史

新增只负责显示的MarkView投影，不把AI EditMark强转成author=user的旧Annotation后写回。显示模型保留markId、origin、visible、retained、可编辑/只读状态及原生几何；源锚点与便签placement分开。旧原生PDF内嵌批注仍由PDF.js只读显示，不进入应用编辑历史。

现有人工高亮/下划线/删除线/便签/线条/箭头/画笔、删除与整笔擦除接到同一执行器；已有工具按钮布局不大改。显隐、固定、颜色/内容修改提供最小明确入口；几何和换锚点按当前库实际支持范围操作，不冒称文字任意拖移或局部擦除。

普通提交只刷新差异涉及的页面/标识；隐藏只影响投影，不删对象。新标识未固定也保存恢复。便签移动只变placement，不能改源quote/quads。临时证据强调仍不是永久标识，不进入编辑历史。

成功回执后从同一权威重读受影响标识/版本再更新页面；失败保留可重试草稿，不提前弹历史。撤销/重做按钮选择明确操作组，遵循当前执行actor的分支及新版本规则；文档切换后按各自历史恢复，不能撤销另一文档或覆盖其他来源的新修改。来源标识和“已保存/待保存/待确认/只读”状态用简短文案呈现。

## 7. 导出与兼容出口

保留现有原PDF只读、另存临时核验后提交的链路；新编辑内容不反向长期双写旧annotations以取悦旧导出。所选新标识的实际PDF导出需单独接EditExportSnapshot、支持类型/placement及原文件核验。

本批未接真实快照导出时：有新编辑状态的文档不能悄悄调用旧导出后显示“全部批注已导出”。入口明确显示未接入状态；如用户选择仅导出未转换的旧批注，必须先说明实际范围。存在已转换/修改旧对象时，不使用冻结旧行导出过期版本。旧未转换文档的既有导出保留并回归。

导出门禁单独完成前不发布面向普通用户的替换包；候选仅使用隔离profile验收，不覆盖正式版。export_marked_pdf仍返回真实UNSUPPORTED，不产出假路径或静默遗漏浮动标识。

## 8. 两项工作包与验收

这里只固定拆分与验收，不是已批准的详细编码计划；本文审阅通过后再写逐文件/命令/TDD步骤。

### 工作包1：正式仓储适配、升级与旧对象核验

- 合成v4库备份→v5→关闭重开；升级中断/锁忙/磁盘失败后回退，未知更高版本不改动。
- 旧文字核验、只读兼容及显式重新定位；重复句、双栏、旋转/裁剪/斜向、扫描页、缺源/替换源、中文/空格路径。
- 新对象、墓碑、锚点、历史、回执、确认与legacy映射在真实Workspace临时库内一致，不以测试helper替代生产适配。
- 双连接冲突、提交前/后取消、提交后丢回执、重启重复请求、AI保护合同回归；原PDF与迁移前备份哈希不变。

### 工作包2：薄IPC与人工真实PDF闭环

- 七类工具实际创建/修改/删除与受支持的几何操作；跨页批量、显隐、固定；只读旧对象可辨认且不重复绘制。
- 撤销/重做、撤销后新编辑、切页/切文档迟到回执、失败草稿重试、正常关闭/强制结束重启；验证实际界面和SQL内容，不只看IPC调用次数。
- IPC拒绝伪造来源/会话、未知命令、任意路径和过期上下文；不加载主进程Node模块到renderer。
- 原阅读/导航/搜索/缩放/批注/旧导出回归；真实候选EXE串行测试。200页约32MiB/1000标识原性能门禁不放宽：启动中位数≤1500ms、帧p95≤34ms、保存p95≤20ms、canvas≤30、缩略图≤8；密集画笔沿用既有断言。
- 首次锚点解析、旧对象核验耗时另报，按页按需，不以排除这些等待冒充完整交互性能通过；若冲突，先记录瓶颈与测试证据再调整实现，不直接改阈值。

每项先RED后GREEN并独立Review，两项后整轮Review。未完成生产闭环前，状态仍是implemented=false；库416和旧EXE141不重新计作新接入验收。

## 9. 后续与复用提示

后续顺序：选定快照真实导出与迁移恢复加固 → AI共享操作/确认入口 → 全文上下文与问题驱动Cruise；Surfing和前端重写继续独立设计，不混入本批。

```text
接续Enlumor编辑库生产接入，先读本设计、WAVE_A_TASKS.md及WAVE_A_STATE.json。
旧数据保留，原文核验成功才转换；失败可见只读，手工重新定位需明确确认。
同一Workspace数据库、主进程执行器、薄IPC与只读显示投影；不长期双写旧annotations。
按正式仓储/迁移与真实人工闭环两项实施，先测试后实现，每项Review，两项后整体Review。
只用隔离profile，不迁移个人库、不改原PDF、不调用模型、不发布或推送。
新标识真实导出另设门禁，缺失时明确范围，不用旧导出假装包含新编辑。
```

自审：原生坐标/来源/保留/显示/导出分开；结构迁移不假造源锚点；只读旧对象与有效新快照隔离；回执与UI状态分离；没有把兼容冻结行作为长期同步权威。实现细节和测试证据在书面设计审阅后的计划中固定。
