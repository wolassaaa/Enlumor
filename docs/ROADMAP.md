# Enlumor 路线图（2026-10-27 代码冻结后）

这份文档写给想知道"Enlumor 接下来做什么、为什么需要资源"的人。现状和实测数字见[当前开发状态](CURRENT_DEVELOPMENT.md)。

## 现在做到了哪一步

Enlumor 是一个能日常使用的原型，一个人开发：

- **阅读与批注**：搜索、跳页、缩放、旋转、标签页、缩略图；高亮、下划线、删除线、便签、箭头、画笔。全部存在本地，导出批注时另存一份 PDF，不改原文件。Windows 0.1.15 已正式发布。
- **新编辑库已经是默认链路**：每次修改都有记录，撤销和重做在重启后仍然有效；旧工作区自动升级，升级前先做备份，并留有退回旧链路的开关。
- **Surfing 全文共读**：针对整篇论文提问。模型先翻页、读原文、搜索，再回答；回答涉及论文里好几处时，会一步一步带着读者看过去，页面平滑滑到对应位置，需要时放大。可以让它自动往下走，也可以按空格自己翻。思考程度用的是模型自己提供的档位。
- **真实模型验收工具**：带二维码的测试 PDF，App 扫码后进入测试模式自动打分；另有一套命令行验收脚本，每次运行都会生成截图报告。

## 还没解决的问题，以及为什么需要资源

下面三项是研究问题。写代码只是其中一部分，大部分工作量在反复的真实模型实验和阅读实验上。

### 1. 让 Surfing 换了模型也一样可靠

**已经知道的**：用 DeepSeek V4.1 Flash 和默认思考档，三套题集是 6/6、8/8、13/14（另有 1 项需人工确认），App 内测试模式 22/22。关掉思考后，模型用时少了将近一半，但遇到看图的题常常不打开图就直接作答。

**还不知道的**：到目前只测过这一个模型。同一套工具和提示词，换成 OpenAI、Claude、Qwen、Gemini 等模型，表现会怎样？思考档位、论文长度、扫描页又各有多大影响？同一道题重复问十次，答案稳不稳定？

**要做的**：

- 建一个评测矩阵，覆盖模型 × 思考档位 × 题集，每题重复多次。
- 把题集扩到更多论文和题型：看图、读表、跨页推理，还有"论文叙述和数据对不上"这类需要批判性阅读的题。
- 用模型自带的结构化输出（例如 JSON 模式）代替现在的纠错回合，并测量这样做是否更快、更省。

**需要的资源**：主要是各家模型的 API 调用额度。一次完整的矩阵评测要跑上百次真实请求，每加一个模型、一个档位，次数就成倍增加。

### 2. 重新做 Cruise：围绕读者的问题陪读

**背景**：旧版 Cruise 一块一块往下读，试用下来发现方向不对：读者是带着问题读论文的。新方向是围绕整篇论文和读者自己的研究问题陪着读，当前页和选中的文字只是补充。

**研究问题**：AI 什么时候该开口，什么时候该保持安静？怎样提示才不打断阅读？怎样判断读者真的读懂了，而不只是拿到了答案？

**要做的**：在 Surfing 已有的底座上做原型；再找同学做小规模阅读实验，用同一篇论文、同一个问题，比较三种情况：不用 AI、直接给答案、一步步带着读。

**需要的资源**：API 额度，加上参与实验同学的时间。

### 3. AI 和人共用一套编辑库

**现在**：编辑库已经能区分一条修改来自用户还是来自 AI，但 AI 还没有写入的入口。

**要做的**：

- AI 提出标注，读者确认后才写入。AI 的标注默认是临时的，可以撤销，并且标明来源。
- 在页面上直接拖动便签、线条端点和画笔。现在只能在批注卡片里输入数值来调整。
- 跨文档检索和导出标注。

## 工程上的待办

- **大量笔画时的界面卡顿**：在 1000 笔、每笔 256 个点的页面上，擦除一次后界面最长卡 79–120 ms，目标是 50 ms 以内；擦除加撤销的总时间在 858–1103 ms 之间，正好卡在 1000 ms 的预算上下。主进程这一侧已经从 691 ms 降到约 110 ms，剩下的问题在界面每次都整页重建，需要改成增量更新。
- **几项偶发失败的端到端测试**：保存失败后重试、部分 Cruise 计时测试、dense-ink 性能预算。机器负载高时会失败，需要逐个查清原因。
- **macOS 版**：还没有构建和验收。
- **开源许可**：项目许可证还没选定。PyMuPDF 是 AGPL／商业双许可，公开分发前必须先处理。

## 更远的方向（只是记录，没有排期）

- **不需要对话框的阅读**：解释、提问提示和证据定位，改用字幕、就近气泡和临时标注来呈现，屏幕上平时只留原文。
- **画笔与文字行融合的高亮**：保留手画的自然感，同时识别并关联到文字行。
- **跨文献的研究记忆**：记住读者在多篇论文之间的问题和发现。

这些方向的出发点都来自真实的阅读问题，详见 [BACKLOG](BACKLOG.md)。
