# Surfing 阅读 agent：我们遇到的问题，从底层到顶层

依据：`feat/editing-default` 分支的代码（代码冻结时的最新版本）、`.cache/acceptance/` 里 34 份真实模型报告、冻结时的 `docs/ROADMAP.md` 和 `docs/CURRENT_DEVELOPMENT.md`。除了标注"估算"的地方，数字都来自这些记录。

注意：`main` 还没有这些工作，它们在 PR #3、#4、#5 里，三个都还开着。演示和讲述都要以 `feat/editing-default` 为准。

## 一句话版本

用 DeepSeek 读一篇论文、答文字题，这件事已经基本做成了。还没解决的是四件事：模型该看图时不一定看，只验证过一家厂商，题集太小且只查关键词，以及还没有证据证明读者因此读懂了。

## 第 1 层：PDF 变成模型能读的东西

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 模型读到的是抽取的文字，图里画的内容读不到 | 图 2 的标签只画在图里，需要看页面图片才能答对 | 已有 `view_page` 绕过，但依赖第 3 层 |
| 扫描页和长论文没有验证过 | 题集只有 4 页和 11 页的论文；抽取上限是 16 万字符、5000 段 | 未测 |
| 带标题、章节的结构信息没有给模型 | 模型拿到的是平铺的段落和图表索引 | 未解决，影响未测 |

## 第 2 层：模型接口和输出格式

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 思考型模型把输出额度用光，或者超时 | 早期 3 份报告共 9 次超时，2 次输出被截断 | 已解决：改用模型自身的输出上限后，后面 23 份报告没有再超时 |
| 模型不总是输出合法 JSON | 164 次提问里报告记录到至少 10 次纠错；纠错后仍失败 1 次，之后没有再出现 | 已缓解：宽容解析加一次自动纠错 |
| 全靠提示词约束格式，没用厂商的 JSON 模式或原生工具调用 | 代码里没有 `response_format` 或原生 tool calling | 未解决，路线图已列 |
| 各厂商差异写死在循环里 | spark 只能单步，dashscope 和 spark 不给图 | 未解决，加厂商时会变重 |

## 第 3 层：工具调用（核心难点）

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 该看图时模型不一定看 | 43 次看图题里 8 次没开页面就答。提示词加强后，最新一轮默认档仍有 1 次；关掉思考时两题全跳过 | **未解决** |
| 没看图也可能答对，分不清是读的还是记得的 | 冻结文档已确认：一道图题靠对名论文的记忆答对 | 未解决，见第 5 层 |
| 三个工具里两个几乎没人用 | 164 次提问：看图 36 次，重读 5 次，搜索 3 次。因为每次请求已经带着全文 | 需要重新设计。长论文放不进全文时，这两个工具才真正有用，尚未验证 |
| AI 还不能写，只能读 | 编辑库能区分修改来自用户还是 AI，但 AI 没有写入入口 | 未开始。这才是"agent 操作我的 PDF"那一步 |

第 3 层的本质：模型自己决定要不要调用工具，提示词只能劝，不能保证。下一步要试的是由应用强制（比如识别到问题涉及图，就先把页面给模型），以及厂商提供的强制调用能力。

## 第 4 层：循环和运行记录（harness 本身）

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 中间过程不留存 | 报告存最终答案、动作摘要、耗时和截图；模型每一步的原话和工具返回的内容不落盘 | 未解决。"它为什么没翻页"目前查不出来 |
| 不知道实际花了多少 token | 代码没有读取厂商返回的用量 | 未解决 |
| 每一步都重发全文 | 代码注释写明"Each step resends the paper"。Attention 每次请求约 1.2 万 token（估算） | 实际花费未知：有缓存时输入价能降很多，但没有测量 |
| 步数上限（4 步、3 动作、3 张图）是拍的 | 没有比较实验 | 未测 |

已经做对的，讲的时候可以骄傲地说：答案引用必须是论文里真实存在的段落，动作只读，请求绑定文档版本，论文文本当作不可信数据，不偷偷重试花钱。

## 第 5 层：评测

| 问题 | 证据 | 状态 |
| --- | --- | --- |
| 只测过一家厂商 | 34 份报告全是 DeepSeek：flash 29 份，v4-pro 5 份。其他厂商只有本地假数据测试 | **未解决，资源的主要去向** |
| 题集太小 | 2 篇论文，其中一篇是合成的；共 16 道问答题 | 未解决 |
| 用名论文测，分不清"读"和"记得" | Attention 太有名，模型不读也可能答对 | 未解决。合成论文 Lumen 能规避，但只有 2 道问答题 |
| 评分只查关键词 | 正则检查必须出现和不能出现的词，判断不了解释好不好 | 未解决 |
| 没有重复测量 | 同一难题集在后期几轮波动于 12 到 14 分之间，同时代码和思考档也在变，分不清原因 | 未解决 |

这一层已经有的东西很难得：题目装进 PDF 的二维码，打开就能测；每次自动生成带截图的报告；还有一题专门考论文里没有的答案，看模型会不会编。

## 贯穿所有层：一个人做的边界

- 一个人开发，没有导师或固定评审。需要的是懂"怎么验证一件事做成了"的人，不一定懂 agent。
- 工具链很新，没有成熟教材，只能靠反复实验。
- 工程待办：1000 笔画时界面最长卡 79 到 120 毫秒（预算 50 毫秒），几个端到端测试偶发失败，macOS 未构建。

## 钱花在哪：可以直接讲的账

每次请求的体量：Attention 全文约 3.3 万字符，加格式约 1.2 万 token（估算），平均每题约 1.5 次请求（估算），每次输出按 1500 token 假设。

**只用 DeepSeek Flash 跑一轮现有题集：约 0.2 美元以内（估算）。** 所以单模型的花费不是障碍，不要这样讲。

花钱的是覆盖面。按下面的矩阵估算一次完整评测：10 篇论文，每篇 15 题，5 个模型，2 个思考档，每题重复 5 次，共约 1.1 万次请求。

| 模型 | 每百万 token 输入/输出（美元） | 一次矩阵（不计缓存） |
| --- | --- | --- |
| Claude Haiku 5.5 | 0.10 / 0.50 | 约 4 美元 |
| deepseek-flash | 0.3 / 1.2 | 约 12 美元 |
| deepseek-v4-pro | 1.32 / 3.96 | 约 49 美元 |
| Claude Sonnet 5.5 | 2 / 10 | 约 88 美元 |
| Claude Opus 5.5 | 4 / 20 | 约 176 美元 |
| **合计** | | **约 330 美元** |

价格是 2026-11-02 官方页面的高峰价。DeepSeek 非高峰减半，缓存能再省一些，所以这是偏保守的上限。OpenAI 官方页面没读到，Gemini 和 Qwen 没有拿到官方价，都没有算进去，加入后总数会上升。

矩阵要跟着改动反复跑，假设三轮就是约 1000 美元。除此之外的资源：参与阅读实验的同学、一位定期看验证方法的老师、开发用的 AI 编程额度。

## 讲的时候的口径

可以说：
- 文字题在 DeepSeek 上基本稳定，难点已经从"能不能跑通"移到"换了模型还可不可靠"。
- 模型会跳过看图，提示词解决不了，这是一个我们亲手测出来的 harness 问题。
- 我们有自己的评测工具，所以每一分钱都换得回一个可比较的数字。

不要说：
- "已经支持各家模型"。只有 DeepSeek 经过真实验证。
- "AI 能操作 PDF"。现在只读。
- "用户读得更好了"。还没做实验。
- "模型调用太贵所以需要钱"。单模型很便宜，贵的是覆盖面和人。
