# Enlumor 功能逐项交付清单

来源：CoReader_MVP_PRD_v0.1.md（产品现名 Enlumor）。状态按子项记录，部分通过不等于整个需求完成。

## 每次发布门禁

使用 Superpowers：systematic-debugging → test-driven-development（先见失败）→ verification-before-completion。
`npm run release:verified` 顺序执行类型检查、Vitest、Python unittest、构建内置 PDF 程序、暂存 ZIP、真实 Electron E2E、无外部 Python 的打开/导出、实际暂存 EXE 性能测试。
任一步失败不更新 release/latest.json。成功后才生成不可变版本文件与最新版本指针；发布测试仅使用独立临时工作区，不修改个人数据。新版首次运行涉及数据库升级时先备份，不删除原批注。
合成压力样本：200 页 + 32MiB 流 + 1000 个真实批注；滚动 p95≤34ms、保存 IPC p95≤20ms、解压后启动三次中位数≤1500ms、正文保留 canvas≤30、缩略图 canvas≤8。这是本机回归预算，不是所有电脑/所有 PDF 的性能保证。

## 每完成两个任务做一次整体 Review

用户新增要求（2026-10-15）：每完成两个独立功能任务，先审查程序与操作体验，再推进下两项；对照成熟工作台/阅读器的官方设计，修正实际问题，不仅装修界面。轮次、发现与修复记录见 [REVIEW-CADENCE.md](REVIEW-CADENCE.md)。
第1轮：侧栏/标签；第2轮：单页/下划线；第3轮：删除线/直线。三轮 Review 已完成，Important 均以失败→成功测试验证；计数清零。

## 已知情况

合成样本基线滚动本身没有 >50ms 长任务，尚未复现用户具体 PDF 的严重卡顿；需要代表性文件继续定位图像解码、复杂矢量或显存压力。
解压包未代码签名；独立 Acrobat Reader 尚未验收（本机 Edge PDF 引擎已检验）。8 项中危告警位于构建开发依赖，生产依赖审计为零（上轮记录）；不自动升级破坏锁定版本。
最终独立审查发现“性能预算只测开发进程而非暂存包”，已增加测试并改为传入 EXE 时全程启动该 EXE。低优先级：发布复制中断可能留下半成品版本目录，最新指针仍不变，但同版本重试需处理该目录。
