# Enlumor · 文档编辑指令库设计

日期：2026-10-19；2026-10-20 修订 v2。状态：待用户审阅；编辑运行时仍未实现。

## 1. 目标与当前事实

用户要求在基础指令执行器之后补齐整个文档编辑指令库，人工和AI使用同一业务能力，而不只提供读取与翻页。范围是Enlumor的页面标识/批注编辑，不扩展成修改PDF正文排版的通用编辑器。

基础执行器653acb4与真实PDF接入2d45f0e已完成：上轮261单测、141完整候选EXE和整轮独立Review通过。当前可执行目录仍只有五类阅读/导航指令。现有Annotation只允许author=user，SQLite仍保存该旧结构；不能直接把AI操作传给applyAnnotationChange后宣称完成来源隔离/浮动标识。

本设计承接[全文上下文与操作库设计§4.1](2026-10-19-reading-command-foundation-design.md#41-共享标识底座来源独立浮动呈现可选导出)。基础两项均已收口，不重复开发。2026-10-20能力审计实测16/16编辑命令名返回COMMAND_INVALID、业务端口调用0；既有人工批注IPC不代表新编辑命令可调用。

## 2. 完整能力目录及差距

| 操作族 | 拟提供的编辑命令 | 已有可复用能力/实际缺口 |
| --- | --- | --- |
| 查询 | list_marks / get_mark | 可读取旧批注；新标识来源、显隐、固定状态尚无模型 |
| 创建 | create_mark | 现有高亮、下划线、删除线、便签、直线、箭头、画笔共七类；当前UI写正式批注，默认覆盖标识尚未实现 |
| 内容/样式 | update_mark | 已有颜色和便签内容修改；统一可编辑属性与严格patch校验待补 |
| 几何/位置 | set_mark_geometry / set_mark_placement / replace_mark_anchor | 有原生坐标和点路径校验；箭头端点调整、移动/缩放等共享编辑API及浮动呈现偏移尚未接入 |
| 删除 | delete_marks | 可复用批量AnnotationChange及逆操作思想，不直接删除其他来源的受保护内容 |
| 擦除 | erase_ink | 现有整笔相交判定与批量删除；不是笔迹局部切分，不能冒充橡皮擦任意路径编辑 |
| 历史 | undo_edit / redo_edit | UI已有会话逆操作历史；需要抽出共享、带来源与版本归属的接口，不能盲目调用全局undo |
| 显隐 | set_marks_visibility | 新能力；隐藏不等于删除、解除固定或不保存 |
| 保留 | set_marks_retention | 新能力；固定/解除固定与来源、显示、导出相互独立 |
| 批量操作 | apply_edit_batch | 全量校验、一次原子提交、一个逆操作；不能部分成功后才发现非法项 |
| 导出 | prepare_mark_export / export_marked_pdf | 已有另存和PyMuPDF链路；按人工/AI/所选标识导出、浮动布局映射与快照一致性尚未支持 |

命令目录是目标，不代表已可调用。只有具有真实实现、测试与宿主支持的命令进入可执行目录；不注册返回空成功的占位工具。画笔/文字行识别融合高亮FUTURE-03继续暂缓；现有七类标识不因此重写识别算法。

## 3. 标识对象与来源

- 共用标识基础与存储权威，不强制人工/AI具有相同外观、展示分组或生命周期。创建来源由宿主可信actor上下文赋予，模型参数不能冒充user或改写来源。
- 新标识默认非永久覆盖标识，支持工作区恢复；fixed/visible/origin分别管理，导出不是“转永久”。旧人工批注按已保留内容保留，不暗中改成可自动清理项。
- 原文锚点和浮动呈现位置分开：移动标签的显示偏移不改原文引用；更换原文锚点使用另一个明确命令并重新校验。高亮等文字标识不允许仅移动矩形却保留已经失真的引用。
- 几何仍使用未旋转PDF原生坐标。箭头/线条/画笔的点路径与包围范围保持一致，编辑后不越页、不接受NaN/退化路径；浮层显示偏移不能当成原文坐标保存。
- 核心模型为markId、文档/指纹、七类标识内容和几何、anchor/placement、来源、固定/显示状态、对象版本。确切TypeScript定义在本草案确认后的实施计划中固定；不直接修改旧Annotation来绕过author校验。

## 4. 指令执行与共享业务边界

沿用requestId、文档指纹、宿主失效版本和AbortSignal，不另建通用Agent引擎。编辑器从宿主取得当前标识快照与能力，不创建第二份有同等权威的sidecar或私有数据库。

编辑指令先严格解析，验证当前文档、对象存在性/版本、属性白名单、原文锚点、几何及操作者，再生成before/after和逆操作。完成所有检查后，宿主以原子compare-and-commit提交，成功才更新界面和历史。失败/取消不写半成品，不以返回变更计划冒充实际保存成功。

AI可以直接编辑本轮自身未固定标识；涉及用户标识、已固定标识或其他受保护对象时生成可核验候选差异，只有用户明确确认才能提交。确认凭据由宿主绑定具体差异/基础版本，不能让模型传confirmed=true绕过确认。预览后对象发生变化即返回版本冲突，不能重新套用旧差异。

undo/redo针对明确操作组和所属来源，不允许“撤销AI”顺便撤销用户的新修改；撤销也是版本校验后的事务。撤销后再编辑要清除相应redo分支，数据库失败时不得先弹出历史项。批量命令也遵循这些规则。

## 5. 导出与持久化

查询、准备变更、提交、保存工作区、导出PDF是不同结果状态。先实现库合同与可测试业务逻辑，再接真实工作区/阅读器/导出适配；适配未完成时不能声称软件已支持完整编辑。

导出由用户选择人工、AI或具体标识，可以选择未固定标识。使用指定版本的标识快照生成新的PDF，不能在导出过程中混入后来编辑的状态；原PDF和工作区固定/显隐状态不变。路径由主进程对话框取得，取消不生成假成功文件。

已有标准批注链路尽量复用；不支持原生PDF表达的浮动标签/动态效果必须显式说明并先确定可验证呈现方案，不能静默漏掉或仅截当前屏幕。输出临时文件核验后另存，导出失败不损伤源文件。

涉及新模型持久化时使用隔离测试库；SQLite升级有备份和恢复测试，旧0.1.15及个人库不迁移。纯指令库阶段不提前改数据库版本。

## 6. 验收边界

1. 七类标识创建与合法属性修改均可复现；移动、箭头端点编辑和原文换锚点分别测试，不用颜色修改冒充几何编辑。
2. 人/AI来源不可伪造，显隐、固定与导出独立；拒绝候选差异不改变原对象。
3. 批量中存在一个非法对象时全部不提交；并发编辑/切文档/暂停拒绝旧操作。
4. 撤销、重做、撤销后新编辑、事务失败及历史恢复正确；重复提交同一操作不会重复创建标记。
5. 编辑器纯逻辑、真实SQLite事务、实际页面显示及导出分别给证据；mock测试不冒充真实端到端支持。
6. 正式接入后验证原坐标旋转/裁剪/缩放、重复导出、已有批注、原PDF哈希及原性能门禁，阈值不放宽。

## 8. v2 审阅补齐：执行结果与生命周期（提案，待用户确认）

### 8.1 保留、显隐与来源

fixed 表示保留及AI修改时的保护条件，不是“是否落库”。未固定标识仍可随工作区恢复；visible=false 只隐藏，不删除、不解除固定，也不自动排除导出。默认不启动自动清理；暂停、关面板和切文档均不删除标识。后续若新增清理策略，需要单独显示范围并支持撤销，不借fixed=false暗中引入。

创建来源由宿主actor/session绑定且不可通过update改写。AI可直接编辑当前宿主会话自身未固定对象；其他会话AI对象、用户对象及固定对象按保护对象走具体差异预览/确认。旧人工内容保持原有保存语义；未来迁移的映射另有测试，不通过改变旧author校验直接接纳AI对象。

### 8.2 原文锚点与自由绘制

文字高亮/下划线/删除线的quote和原文quads来自同一已验证源页的锚点解析；原生坐标合法不等于已经证明引用真实。换锚点重取原文；标签placement只改变展示，不改引用。自由线条/箭头/画笔的几何可走严格页界和路径校验，但不自动成为有原文依据的引用。页宽高来自宿主源文档，不采信调用者提交的页面尺寸。

### 8.3 提交线性化点与取消

比较版本、权限确认、变更集和逆操作通过后，宿主原子提交持久事务的成功点是提交线性化点。到达该点之前的取消/切文档使整个操作不提交，也不更新历史或成功回执。

提交后取消不倒退已经保存的事实：返回或恢复查询的结果仍是committed并带明确操作ID，不把已保存结果改成纯canceled。迟到的committed回执保留文档/操作归属；新文档界面通过归属校验忽略其旧界面效果。此时需要撤回内容，应发新的、有版本校验的undo_edit，而不是声称取消已经回滚。

数据库busy、磁盘失败和不确定的提交结果都由宿主结束/确认事务后报告。比较检查及实际提交不得隔着可被其他写入插入的空隙；SQLite测试需使用真实并发连接制造冲突，不以Map mock代替。事务发生前后的失败分开记录，绝不在事务失败前先更新UI或弹出历史。

### 8.4 幂等回执与请求复用

宿主以文档指纹、可信actor/session、requestId绑定规范化命令及预期版本的摘要。相同请求重投查询幂等回执，不重复创建或再次推进历史；同一个键对应不同摘要时返回REQUEST_ID_REUSED，不用新参数覆盖旧结果。

变更、逆操作所需数据及幂等回执属于同一提交边界。进程在提交后、回执到达前中断，重试仍能查出已经committed的操作。完成记录保留策略必须覆盖宿主承诺的重试窗口；详细配额在审阅后的计划固定。纯测试仓储的幂等行为不被描述成生产工作区已经持久化回执。

### 8.5 确认与历史一致性

确认凭据绑定完整before/after摘要、基础对象版本和可信actor；对象或来源变化后重新预览。凭据消耗与成功提交同事务；失败或提交前取消不把凭据永久消耗。调用方传confirmed=true没有确认含义。

undo_edit/redo_edit定位明确操作组，比较当前对象与该组预期版本；其他新编辑导致冲突时拒绝覆盖。对象版本单调递增，撤销内容不把版本号倒回旧值。撤销后新编辑清理所属历史分支的redo；事务失败时undo/redo栈不变。跨来源的新人工修改不被“撤销AI”一起撤销。

### 8.6 导出选择与不支持结果

准备导出接收显式选择：来源、明确ID集合与是否包含隐藏标识；visible不是导出过滤器。固定/未固定均可被选择，导出不会改变保留状态。实际导出绑定准备时的文档指纹、标识版本和快照摘要；后续修改不会悄悄混入同一个文件。

标准PDF批注优先复用既有链路；某种placement/浮动效果尚无可验证PDF表达时，返回UNSUPPORTED_MARK_EXPORT及具体标识ID，用户调整选择或明确接受有定义的降级后再生成新预览。不静默丢弃、不用当前屏幕截图冒充完整PDF。文件对话框取消返回cancelled，目标生成与源PDF状态分开。

### 8.7 首批库验收与生产接入分开

第一批两项仍为合同/纯变更与执行器/事务历史。所谓真实本地仓储验收，是测试自行创建的新SQLite文件和隔离测试schema，明确不是生产Workspace v4迁移，也不是第二个用户存储权威。

这两项结束后仅称“库合同与隔离事务行为已验证”。生产工作区迁移、阅读器真实显示、人工/AI共同入口和选定快照实际导出另列后续接入批次；这些门禁完成后才称软件支持完整编辑。各命令只有对应生产宿主具备实际能力时才进入可执行目录；纯端口、预览或未支持状态均不返回已保存/已导出成功。

### 8.8 修订验收案例

1. 提交前abort：零变更/零历史；提交成功后abort：可查询同一committed回执，当前新文档界面不被旧结果影响。
2. 同requestId同摘要重投：同操作结果且只一次变更；不同摘要：REQUEST_ID_REUSED。
3. 用户编辑夹在AI变更与undo之间：undo冲突，不覆盖用户内容；成功撤销时对象版本继续增长。
4. fixed=false且visible=false后重启：对象仍可恢复；显式选择该对象可准备导出，保留状态不变。
5. 确认后的对象版本被另一连接修改：整批拒绝；提交失败时历史与凭据消耗不前移。
6. 选中的浮动标识没有PDF表达：UNSUPPORTED_MARK_EXPORT，不产出遗漏标识的假成功文件。

以上是待用户审阅的行为要求，不是已实现或已运行的编辑测试结果。上轮基础层261/141为历史实测记录，不作为本轮草案文档检查的测试计数。
