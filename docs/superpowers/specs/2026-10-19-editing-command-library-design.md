# Enlumor · 文档编辑指令库设计

日期：2026-10-19。状态：待审阅草案，尚未实现。

## 1. 目标与当前事实

用户要求在基础指令执行器之后补齐整个文档编辑指令库，人工和AI使用同一业务能力，而不只提供读取与翻页。范围是Enlumor的页面标识/批注编辑，不扩展成修改PDF正文排版的通用编辑器。

现有653acb4只实现五个读取/导航执行器合同，尚未接入真实阅读器。现有Annotation只允许author=user，SQLite仍保存该旧结构；不能直接把AI操作传给applyAnnotationChange后宣称完成来源隔离/浮动标识。

本设计承接[全文上下文与操作库设计§4.1](2026-10-19-reading-command-foundation-design.md#41-共享标识底座来源独立浮动呈现可选导出)。基础执行器已完成，不重复开发；旧计划Task2真实阅读器接入仍单独待办，不用本设计掩盖其未完成状态。

## 2. 完整能力目录及差距

| 操作族 | 拟提供的编辑命令 | 已有可复用能力/实际缺口 |
| --- | --- | --- |
| 查询 | list_marks / get_mark | 可读取旧批注；新标识来源、显隐、固定状态尚无模型 |
| 创建 | create_mark | 现有高亮、下划线、删除线、便签、直线、箭头、画笔共七类；当前UI写正式批注，默认覆盖标识尚未实现 |
| 内容/样式 | update_mark | 已有颜色和便签内容修改；统一可编辑属性与严格patch校验待补 |
| 几何/位置 | set_mark_geometry / set_mark_placement / replace_mark_anchor | 有原生坐标和点路径校验；箭头端点调整、移动/缩放等共享编辑API及浮动呈现偏移尚未接入 |
| 删除 | delete_marks | 可复用批量AnnotationChange及逆操作思想，不直接删除其他来源的受保护内容 |
| 擦除 | erase_ink | 现有整笔相交判定与批量删除；不是笔迹局部切分，不能冒充橡皮擦任意路径编辑 |
| 历史 | undo_edit / redo_edit | UI已有会话逆操作历史；需要抽出共享、带来源与版本归属的接口，不能盲目调用全局undo |
| 显隐 | set_marks_visibility | 新能力；隐藏不等于删除、解除固定或不保存 |
| 保留 | set_marks_retention | 新能力；固定/解除固定与来源、显示、导出相互独立 |
| 批量操作 | apply_edit_batch | 全量校验、一次原子提交、一个逆操作；不能部分成功后才发现非法项 |
| 导出 | prepare_mark_export / export_marked_pdf | 已有另存和PyMuPDF链路；按人工/AI/所选标识导出、浮动布局映射与快照一致性尚未支持 |

命令目录是目标，不代表已可调用。只有具有真实实现、测试与宿主支持的命令进入可执行目录；不注册返回空成功的占位工具。画笔/文字行识别融合高亮FUTURE-03继续暂缓；现有七类标识不因此重写识别算法。

## 3. 标识对象与来源

- 共用标识基础与存储权威，不强制人工/AI具有相同外观、展示分组或生命周期。创建来源由宿主可信actor上下文赋予，模型参数不能冒充user或改写来源。
- 新标识默认非永久覆盖标识，支持工作区恢复；fixed/visible/origin分别管理，导出不是“转永久”。旧人工批注按已保留内容保留，不暗中改成可自动清理项。
- 原文锚点和浮动呈现位置分开：移动标签的显示偏移不改原文引用；更换原文锚点使用另一个明确命令并重新校验。高亮等文字标识不允许仅移动矩形却保留已经失真的引用。
- 几何仍使用未旋转PDF原生坐标。箭头/线条/画笔的点路径与包围范围保持一致，编辑后不越页、不接受NaN/退化路径；浮层显示偏移不能当成原文坐标保存。
- 核心模型为markId、文档/指纹、七类标识内容和几何、anchor/placement、来源、固定/显示状态、对象版本。确切TypeScript定义在本草案确认后的实施计划中固定；不直接修改旧Annotation来绕过author校验。

## 4. 指令执行与共享业务边界

沿用requestId、文档指纹、宿主失效版本和AbortSignal，不另建通用Agent引擎。编辑器从宿主取得当前标识快照与能力，不创建第二份有同等权威的sidecar或私有数据库。

编辑指令先严格解析，验证当前文档、对象存在性/版本、属性白名单、原文锚点、几何及操作者，再生成before/after和逆操作。完成所有检查后，宿主以原子compare-and-commit提交，成功才更新界面和历史。失败/取消不写半成品，不以返回变更计划冒充实际保存成功。

AI可以直接编辑本轮自身未固定标识；涉及用户标识、已固定标识或其他受保护对象时生成可核验候选差异，只有用户明确确认才能提交。确认凭据由宿主绑定具体差异/基础版本，不能让模型传confirmed=true绕过确认。预览后对象发生变化即返回版本冲突，不能重新套用旧差异。

undo/redo针对明确操作组和所属来源，不允许“撤销AI”顺便撤销用户的新修改；撤销也是版本校验后的事务。撤销后再编辑要清除相应redo分支，数据库失败时不得先弹出历史项。批量命令也遵循这些规则。

## 5. 导出与持久化

查询、准备变更、提交、保存工作区、导出PDF是不同结果状态。先实现库合同与可测试业务逻辑，再接真实工作区/阅读器/导出适配；适配未完成时不能声称软件已支持完整编辑。

导出由用户选择人工、AI或具体标识，可以选择未固定标识。使用指定版本的标识快照生成新的PDF，不能在导出过程中混入后来编辑的状态；原PDF和工作区固定/显隐状态不变。路径由主进程对话框取得，取消不生成假成功文件。

已有标准批注链路尽量复用；不支持原生PDF表达的浮动标签/动态效果必须显式说明并先确定可验证呈现方案，不能静默漏掉或仅截当前屏幕。输出临时文件核验后另存，导出失败不损伤源文件。

涉及新模型持久化时使用隔离测试库；SQLite升级有备份和恢复测试，旧0.1.15及个人库不迁移。纯指令库阶段不提前改数据库版本。

## 6. 验收边界

1. 七类标识创建与合法属性修改均可复现；移动、箭头端点编辑和原文换锚点分别测试，不用颜色修改冒充几何编辑。
2. 人/AI来源不可伪造，显隐、固定与导出独立；拒绝候选差异不改变原对象。
3. 批量中存在一个非法对象时全部不提交；并发编辑/切文档/暂停拒绝旧操作。
4. 撤销、重做、撤销后新编辑、事务失败及历史恢复正确；重复提交同一操作不会重复创建标记。
5. 编辑器纯逻辑、真实SQLite事务、实际页面显示及导出分别给证据；mock测试不冒充真实端到端支持。
6. 正式接入后验证原坐标旋转/裁剪/缩放、重复导出、已有批注、原PDF哈希及原性能门禁，阈值不放宽。

## 7. 后续实施拆分（待本设计确认后写详细计划）

- 第一项：完整编辑命令合同、标识校验与纯变更/逆操作生成；明确哪些命令需要宿主确认或导出端口。
- 第二项：编辑执行器、原子提交/版本冲突与撤销重做，通过真实本地仓储适配验收。来源/浮动新模型实际落库必须另有迁移与界面接入验收，不在“指令库已写”时称上线。
- 两项逐项TDD和独立Review，整体Review后再安排工作区/界面/模型接入。沿用子代理方式，当前自动任务不自动恢复。
