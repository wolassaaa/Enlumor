# Enlumor · 全文上下文与阅读操作库设计

日期：2026-10-19。状态：设计草案，待书面审阅；尚未实施。

> 当前实施顺序已收窄：用户要求先做最基础的指令系统；先实施读取/导航合同与真实阅读器适配两项，计划见[基础指令计划](../plans/2026-10-19-document-command-foundation.md)，待计划审阅。后文完整能力/标识设计作为后续要求，不在首批全部铺开。画笔与文字行识别融合的高亮仅登记FUTURE-03，不实施。

## 1. 用户已确认的方向

重建AI共读底座，不再以当前块逐段解释作为Cruise的核心。先让模型实际获得整篇论文的上下文，再围绕持续研究问题返回解释、原文引用和结构化阅读指令。先建立可测试的阅读操作库，再接新的Cruise；其他已稳定功能保留。

用户补充要求：人在文档内能完成的操作，AI也应能通过同一操作库完成，包含箭头等标记的创建与编辑，不只是阅读导航。最新修订统一人/AI标识：默认都是非永久的浮动覆盖标识，用户可选择固定保留。不再采用“人工天然永久、AI天然临时”的双轨模型；来源与固定状态独立。

这是替换旧AI编排与单块上下文约束的具体理由，不是重写整个软件的授权。旧Wave A自动化结果保留为历史工程证据；用户实际反馈表明原产品交互不符合预期，不再把“等待配置密钥”当作唯一缺口。用户报告DeepSeek已配置可用；完整真实验收尚无记录。

## 2. 替换与保留

- 替换：以block索引顺序推进的Cruise控制器、只向模型提供一个block的核心输入、把继续等同于下一块的交互。
- 保留：PDF.js显示、文字提取、原生坐标映射、文档身份校验、批注/撤销/保存/导出、已有服务协议和凭据隔离。
- 复用：readPageBlocks、locateCruiseBlock、阅读器页码导航、clearCruiseFocus、既有取消与迟到响应保护；reading-commands.ts由现有三个有限命令扩充，不另造总线。
- 本轮不做：通用Agent平台、插件注册系统、任意代码执行、多文档研究、Surfing自动调度、白板和无对话框沉浸界面。

## 3. 数据先于指令：全文上下文包

应用先提取全文，形成不可混淆的文档快照：documentId、fingerprint、contextRevision、页数、按阅读顺序排列的passages，以及文字/图像能力说明。每段包含应用生成的稳定passageId、原文、页索引；章节信息在可可靠提取时提供。

本地映射保持 passageId → 原文 → 未旋转PDF坐标quads → 页索引。模型只收到所需文本和来源标识，不负责生成坐标。一个概念可能有多个原文证据，不强制压成单个矩形。

准备全文不等于渲染全文：按需读取文本、允许取消、让出界面执行时间，不能把200页canvas同时挂载。复用已有提取器；若现有分块对某种布局缺失/错序，显式标明，不宣称完整可靠。

模型请求默认携带完整论文文本及ID映射、持续研究问题和有界的相关会话。不能只发送摘要或检索结果却显示“全文已进入上下文”。API若是无状态，每次请求都要实际携带必要上下文，不能假设第一次发过就永久记住；厂商缓存是可选优化，不是正确性依赖。

从旧版“仅当前块外发”改为全文外发时，界面须明确显示当前文档、全文范围、目标服务及不含哪些视觉内容，由用户手动提交后才发送；打开PDF或准备本地快照本身不触发模型请求。沿用凭据隔离，不在请求说明、日志、文档或聊天中记录密钥。

上下文容量必须考虑全文、指令、问题、对话及输出预留；模型实际容量需明确配置或有可靠能力信息，不能凭显示名猜测。若全文超限或容量未能确认，给出明确状态，用户选择分层/缩小范围后才继续，不静默截断。只有文字提取的PDF不能标为图表/公式视觉已理解；扫描无文字页不得伪造全文。

## 4. 第一版阅读操作库

这些是应用内有限TypeScript接口，不是任意IPC/文件/命令执行入口。读取能力返回可检查的数据；模型动作只选白名单中的动作。

| 能力 | 输入/输出与作用 | 复用边界 |
| --- | --- | --- |
| get_document_context | 当前文档快照与全文文本，明确完整/不完整/超限状态 | 现有读块及文档身份 |
| get_reading_state | 当前页、选区passage引用、用户接管状态；不是桌面截图 | 当前阅读器状态 |
| get_passages | 指定合法passageId，返回精确原文及页号 | 本地快照映射，不是重查整篇 |
| go_to_page | 受限页码导航，返回实际到达状态 | 已有阅读器导航 |
| show_evidence | 一组合法passageId及主定位项；跨页定位、展示证据 | 既有定位/临时强调 |
| clear_focus | 清除本轮临时强调 | 既有clearCruiseFocus |
| pause | 取消在途解释/指令，撤销旧请求控制权 | 既有取消语义 |

内部pageIndex从0开始；对模型展示的pageNumber从1开始，适配层集中转换并校验。证据导航优先使用passageId，不让模型自己猜页码。原有多页强调展示能力不足时，只强调主定位页并列出其他证据入口，不冒充已展示全部证据。

上表是读取与导航子集，不是完整能力清单。操作库须对齐文档界面实际可执行的操作，新增工具也要同步检查人/AI覆盖关系；实现计划先清点现有能力，不能以三个阅读命令声称完成全部操作库。

| 操作族 | AI应有的能力 | 默认执行效果 |
| --- | --- | --- |
| 阅读与文档导航 | 搜索、跳页、定位、缩放、旋转、阅读布局及已授权文档切换 | 改变当前阅读视图，用户可接管；不改源PDF |
| 原文标记 | 高亮、下划线、删除线、便签的创建、编辑与颜色调整 | 与人工共用非永久覆盖标识，固定保留由用户选择 |
| 几何标记 | 箭头、线条、画笔的创建及合法属性/几何调整 | 共用非永久覆盖标识；坐标来自可核验锚点或明确页面几何，不猜原文位置 |
| 删除与擦除 | 删除标记、整笔擦除、撤销与重做 | AI可调整本轮自身未固定标识；涉及用户或已固定标识时先预览差异并确认 |
| 保存与导出 | 保存工作区状态；按用户选择固定保留及导出 | 工作区恢复、固定保留、导出PDF各自独立；文件路径沿用原生对话框 |

“能力对齐”只针对文档内操作，不包含读取密钥、任意系统命令或操作无关应用。尚未支持的人工功能不能标成AI已支持；箭头等编辑若现有UI只有创建没有调整，应在能力清点中明确为需要补齐的共享操作，而不是虚报复用完成。裁剪/改写正文/删PDF页面等未有的编辑器能力不因这条原则自动变成本轮任务。

### 4.1 共享标识底座：来源独立、浮动呈现、可选导出

- 人和AI共享锚点映射、操作接口、校验及持久化基础，不强制所有标识具有相同形态、展示流程或生命周期。用户标识与AI标识保留独立来源，可分别分组、显隐、管理与设置样式；共享底层不等于混成无法区分的一层，也不另建两套平行权威数据库。默认非永久，不将“人工创建”直接等同于“永久固定”。
- 默认标识是覆盖在阅读视图上的辅助层，可以隐藏、移动、修改、撤销或清除；需要留下时用户主动选择“固定保留”，也可解除固定。固定保留仍能由用户编辑/删除，不表示不可逆。
- “浮动”包含呈现位置的灵活性：箭头、标签或解释标识可以就近摆放、避让正文，而不是全部被锁成PDF原生批注的外观。原文锚点与呈现位置分开；浮动后仍能找到来源，缩放/旋转/翻页不串到别的原文。高亮这样的贴字形标识仍需精确对齐。
- 来源、固定状态、显示布局和是否导出独立表达。origin=user/ai不会因为固定而改变；“看得见”“已自动保存”“已固定”“已导出PDF”不互相等同。具体字段在实施计划中按最小需求确定，不先搭通用图层框架。
- 非永久不等于瞬时或必然丢失：工作区可通过同一SQLite保存覆盖标识及状态用于恢复，不能暗中把关闭软件或翻页定义为全部删除；具体清理时机在实施前明确。显示/隐藏不删除数据，也不改变固定状态。
- AI可操作本轮自身未固定标识；修改/删除用户标识或已固定标识先展示候选差异，确认前原对象不变。确认时校验基础版本，复用共享业务事务与撤销机制，拒绝覆盖用户在预览期间的新修改。
- 撤销按来源和操作分组区分，但共用操作系统；批量固定/解除固定是可撤销操作。清除当前证据聚焦、隐藏覆盖层、删除未固定标识、删除固定标识是不同动作，不能一次“清空AI”误删用户保留内容。
- 平时标识保存在工作区并覆盖显示，不必直接嵌进PDF；用户可另存“带所选标识的PDF”，选择人工、AI或两者，以及所选标识范围。未固定的浮动标识也可以被明确选择导出，不要求先转永久标识。固定状态、可见状态、来源与导出范围各自独立，导出不反向改变工作区标识状态，源PDF仍不自动覆盖。
- 导出需明确呈现差异：能映射成标准PDF批注的标识沿用现有链路；可移动浮层的布局需要转换为目标PDF页面上的位置，不支持的动态效果不能静默遗漏或声称完整保留。是否提供静态外观导出及页外标签排版在实施前专项确定，不能只截当前屏幕冒充整份PDF导出。
- 已有人工批注视为用户已保留内容；未来引入新模型时保留其坐标、来源与导出结果，不自动改成会清理的非永久标识，不改写个人数据库做未经验证的迁移。

本节取代此前“人工正式批注层＋AI草稿层”的设计；完整字幕气泡共读界面仍属于FUTURE-02，不因统一标识模型而提前实现。

## 5. 模型输出是数据，不是可执行代码

不依赖每家厂商都支持原生tool calling。先沿用现有生成协议，使用严格的JSON结果格式，由应用解析校验；后续协议适配不改变阅读操作合同。

```json
{
  "explanation": "结合全文与研究问题的解释",
  "evidence": ["passage_42", "passage_108"],
  "actions": [{"type": "show_evidence", "passageIds": ["passage_42", "passage_108"], "primaryPassageId": "passage_42"}]
}
```

示例ID只是格式示例。应用在当前快照中校验每个ID、文档指纹、页范围和动作白名单。不存在的证据不得定位，也不能显示为已核验引用；校验失败显示错误并保持用户位置。禁止eval、任意脚本、路径读写或模型直接操作数据库。

一次结果可以包含一组覆盖标识操作及一个主定位目标，所有操作先完整校验，再成组提交；失败时不留下部分修改。第一版一次响应只允许一个可改变视口的动作：go_to_page或show_evidence；冲突或多次视口动作直接拒绝，不执行部分动作后才报错。不合格/未完成的流式JSON不触发动作；完整结果校验通过后再执行导航并呈现可核验解释。取消/网络失败不自动重试，也不留下已执行一半的导航计划。

## 6. 任务上下文与用户控制

应用持有sessionId、goalVersion、requestId、document fingerprint、contextRevision与navigationRevision。模型无需生成这些归属字段，应用将它们绑定到请求和指令执行。

响应返回时及执行导航前均检查归属。用户换问题、换文档、切服务、滚动/翻页/选区/批注/缩放/暂停后，旧响应不得覆盖当前解释或把页面拉回去。异步取页/定位过程中再次接管也要失效，不能只在收到响应时检查一次。

提交问题允许AI基于全文主动选证据并跨页定位，无需用户逐次批准读页和翻页；不允许持续自动翻页。用户可以随时停止，重启恢复为暂停。Surfing未来可以复用读取/映射/导航能力，但自动推进策略不进入本轮。

## 7. 第一条纵向验收链路

1. 用本地Attention Is All You Need建立全文快照；全文每个证据ID能回到真实页与文字，非只检查标题。
2. 离线使用确定性输出驱动阅读操作库：定位非相邻页证据、返回原文、清除强调；非法ID/页码/未知命令/旧版本均拒绝且位置不变。
3. 准备好的全文确实进入请求负载；验证整篇内容未被单块/摘要替代。切服务/目标时上下文不串用；超限、扫描缺文字明确呈现。
4. 新Cruise接入后再做真实模型验收：同篇论文提出两个不同问题，证据路径随问题变化；追问保留目标，能主动跨页定位。真实API与离线fixture分开记录。
5. 验证滚动、批注、切页和暂停中断旧导航；原PDF/个人数据库/既有批注不变。
6. 原性能门禁保留：200页约32MiB/1000批注，启动中位≤1500ms、滚动帧p95≤34ms、保存p95≤20ms、正文canvas≤30/缩略图≤8；密集画笔既有阈值不放宽。
7. 人/AI文档操作能力矩阵逐项验收，不以导航子集代替全部能力。AI创建、修改箭头及标记后，用户已有标识与原PDF不变；人/AI默认均可浮动、非永久，原文锚点可靠，隐藏不删除数据。
8. 创建非永久标识→工作区恢复→固定/解除固定→按范围导出→撤销链路保留来源；人工/AI可分别显隐，显隐、固定与导出不耦合。用户可选择未固定标识导出到新PDF，导出不改变原文件或工作区固定状态。AI建议删除/修改用户或固定标记时，拒绝确认不改原对象，预览后人工修改触发版本冲突保护。

## 8. UI及交付边界

后续右侧AI工作台消费同一套上下文和操作库；顶部文档/批注工具、窄导航、可调整布局与底部折叠记录保持已确认方向，不与操作库互相绑定。远期字幕气泡/动态标注见Backlog FUTURE-02，只记录、不实现。

当前仅形成设计规格与同步状态。书面规格确认后再形成两项实施任务、RED/GREEN测试与子代理执行计划；不在旧逐块Cruise上继续堆补丁，不要求先让被否定的产品流程通过真实验收才准许重建。发布仍需新流程真实验收和完整回归。
