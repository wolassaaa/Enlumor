# Enlumor v0.4 Wave A/B Implementation Plan

> **历史计划提示（2026-10-18）：**当前产品基线为[Enlumor v0.5.1](../../product/Enlumor_Product_Plan_v0.5.1.md)。本文件保留原任务与证据关系；已实施的Wave A继续有效。旧Wave B的摘要硬门槛、先完成问题驱动Cruise再做Surfing的顺序已被取代，未实施条目不再构成执行授权。下一步仅补齐/验收A，之后按新基线单独拆Surfing B两项任务。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 用户带着问题，在原文中得到可验证、不过度推断的证据与解释，始终控制推进。

**Architecture:** 复用现有PDF Core、IPC、模型适配及SQLite。增加有限本地命令入口、目标记录、上下文隔离和检索编排；不构建通用执行平台。模型做语义解释与候选建议，程序验证证据和导航。

**Tech Stack:** 现有Electron + React + TypeScript + PDF.js + node:sqlite + PyMuPDF；不新增运行时依赖。

**Spec:** D:/codex project/Enlumor/docs/superpowers/specs/2026-10-17-v04-wave-ab-baseline.md（包含用户附件路径及SHA256、最新决定）。

**Status:** 用户已批准子代理执行。A1自动化与A2实现审查通过，验收候选139单测/8Python/101打包Electron及原性能门禁通过；A1真实API尚未验收，A不标完成、不发布，B未启动。每轮两项整体review保留。

## Global Constraints
- Windows first / Local first / Source first；原始PDF只读，SQLite是权威存储。
- 仅授权A、B；不新增Surfing入口、预算子系统、工具调用平台或全应用事件溯源。
- 目标版本和缓存隔离随B交付；迟到响应不得导航、替换解释或改读状态。
- 自动化使用临时userData和合成PDF；真实验收由用户在隔离实例配置服务，不读取/打印密钥。
- 每项先RED后GREEN、每项独立提交；每轮review后完整release:verified，失败不改latest。
- 保留已验证0.1.15；版本号仅在准备下一次候选发布时递增，原依赖锁不变。
- 应用目录均相对D:/codex project/Enlumor；原PRD不覆盖。

## Review Focus
1. 旧auto会话重启：只恢复paused/manual，无自动请求，旧批注/进度不丢（A2）。
2. 同目标暂停恢复、目标快速切换、后台：即使服务忽略abort，旧结果也不显示或跳页（A2/B1/B2）。
3. 没有摘要/目录、摘要跨页、中文标题、扫描件：显示真实来源，缺文字层不假确认（B1）。
4. 中文问题对英文论文、关键词零命中、只扫部分文档、关键限制在后页：明确检索范围与不足，不把相似度当支持（B2）。
5. 文件替换、服务配置变化、迁移失败/强退：旧缓存不误用，原库有备份，可重试（B1/B2）。
