# 编辑库：默认批注链路、升级与退回（2026-10-26）

从这一版起，高亮、下划线、删除线、便签、直线、箭头、画笔、整笔擦除默认都走新的编辑库：

- 每次修改都会持久保存，并留有回执。
- 撤销和重做按操作组进行，重启后仍然有效。
- 旧批注会在打开它所在的页面时自动转成新标识。
- 导出批注 PDF 时，写入阅读器里当前看到的样子，包括改过的颜色、改过的便签和已删除的内容；隐藏的标识不导出。

## 第一次启动：自动升级工作区

新版第一次打开工作区（`%APPDATA%\Enlumor\workspace.sqlite`）时，会把它从第 4 版升级到第 5 版，步骤如下：

1. 先用 SQLite 的 `VACUUM INTO` 做一份完整备份：`workspace.sqlite.pre-v5.<时间>-<随机>.bak`。
2. 检查备份的完整性，并逐表比对文档、批注、阅读位置、偏好、模型配置、Cruise 会话，确认和原库完全一致。
3. 比对通过后，在同一个事务里加入编辑库的表。任何一步失败都会整体回滚，原库保持不变。

如果升级失败（例如数据库正被别的程序占用），应用照常启动，继续使用旧批注链路，失败原因写进日志。

## 不想升级：`--legacy-editing`

带 `--legacy-editing` 启动时不升级，继续使用旧批注链路：

```powershell
npm start -- --legacy-editing
```

对已经升级到第 5 版的工作区，旧链路只能读、不能写，也看不到新标识。要真正回到旧版，请按下一节恢复备份。

## 回到升级前

1. 关闭 Enlumor。
2. 在 `%APPDATA%\Enlumor\` 里，把当前的 `workspace.sqlite` 改名留存，例如改成 `workspace.sqlite.post-v5.bak`。
3. 把最新的 `workspace.sqlite.pre-v5.*.bak` 复制一份，命名为 `workspace.sqlite`。
4. 用旧版（0.1.15）或带 `--legacy-editing` 的新版打开。

升级之后才做的新标识不在这份备份里。需要的话，先用新版导出批注 PDF 保存下来。

## 还没做的（路线图）

- AI 和用户共用编辑入口：AI 提出标注，由用户确认后写入。命令库已经支持区分操作来源，界面还没接上。
- 便签拖动位置、调整线条和画笔的几何形状：命令库支持，界面还没接上。
- 跨文档的标注检索和导出。
